# お知らせ記事の制作（1日1本）

オーナーの「Claude用・1日1記事の作成指示書」（2026-11-22）に沿って運用するためのフォルダです。サイトには公開されません（ビルド対象外）。

| ファイル | 内容 |
|---|---|
| plan-30days.md | 30日分のテーマ案（読者の疑問・必要な確認情報・既存記事との差分・状態） |
| history.csv | 制作履歴（date_jst, article_id, title, reader_question, topic, sources, draft_path, published_url, status, google_post_status） |
| drafts/YYYY-MM-DD-*.md | 記事ごとの原稿（管理用情報・SEO項目・本文・Googleビジネスプロフィール投稿案） |

記事の項目（data/news.json）：id, date, title, body, image, status, description（検索結果に出る説明文）, gbp（Google投稿文。1500字以内・電話番号なし）, createdAt, updatedAt

## 毎日の流れ（自動実行：毎日16:37ごろ開始 → 17時ごろ公開）
オーナーの指示（2026-11-22）により、毎日 Claude のスケジュール実行で1本作り、**公開まで**行う。
1. 既存記事（data/news.json）と history.csv を読み、同じ疑問への記事が無い「書ける」テーマを plan-30days.md から選ぶ。その日の記事が下書きで既にあれば、それを確認して公開する。「書ける」テーマが無くなったら、同じ条件で新しいテーマを plan-30days.md に足してから書く。
2. 料金・割引・営業時間などは、その日の公開データ（data/price.json・data/offers.json・app/_lib/site.js・各ページ）で確認する。出勤・空き状況はリポジトリに無い（公開時にスプレッドシートから取り込む）ため、記事に具体的な出勤を書かない。
3. 原稿を drafts/ に保存し、data/news.json に **status: "public"**、Google投稿用の文章を **gbp** に入れて追加する。
4. 検証（validate-data・テスト・ビルド）が通ったら main に反映する。サイトの公開（デプロイ）が成功したことを確認してから、history.csv を published にし、published_url を入れる。デプロイが失敗したら failed にして原因を報告する。
5. Googleビジネスプロフィールへの投稿は、別の仕組み（apps-script/gbp-autopost.gs）が17時以降に記事のページが開けることを確かめてから行う。Claude の作業環境からは投稿の結果が見えないため、posted とは書かない。下の「自動投稿の状態」が「設定済み」なら google_post_status を queued（自動投稿へ引き渡し済み）、「未設定」なら draft（投稿文のみ・手作業で投稿）とする。結果はオーナー宛てのメールと、そのスクリプトの記録（GBP_POSTED）で確認する。
6. 管理画面の「お知らせ」から、公開後の記事の修正・非公開（下書きに戻す）・削除ができる。

## 本文の書き方（お知らせの本文の記法）
- 段落は空行で区切る。行頭が「## 」の段落は見出しになる。
- リンクは `[文字](/system/)` の形だけ使える（HTMLは使わない）。
- 守ること：自分が取材・施術・来店したように書かない／実在しない口コミや体験談を作らない／料金・割引・出勤・空き状況を推測で書かない／医療的な効果を断定しない／性的な連想をさせる表現を使わない／写真から性格や技術を推測しない／順位を約束しない。
