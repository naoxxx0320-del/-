# お知らせ記事の制作（1日1本）

オーナーの「Claude用・1日1記事の作成指示書」（2026-11-22）に沿って運用するためのフォルダです。サイトには公開されません（ビルド対象外）。

| ファイル | 内容 |
|---|---|
| plan-30days.md | 30日分のテーマ案（読者の疑問・必要な確認情報・既存記事との差分・状態） |
| history.csv | 制作履歴（date_jst, article_id, title, reader_question, topic, sources, draft_path, published_url, status, google_post_status） |
| drafts/YYYY-MM-DD-*.md | 記事ごとの原稿（管理用情報・SEO項目・本文・Googleビジネスプロフィール投稿案） |

## 毎日の流れ
1. 既存記事（data/news.json）と history.csv を読み、同じ疑問への記事が無いテーマを plan-30days.md から選ぶ。
2. 料金・割引・営業時間などは、その日の公開データ（data/price.json・data/offers.json・app/_lib/site.js・各ページ）で確認する。出勤・空き状況はリポジトリに無い（公開時にスプレッドシートから取り込む）ため、記事に具体的な出勤を書かない。
3. 原稿を drafts/ に保存し、data/news.json に **status: "draft"** で追加する（サイトには出ない）。
4. オーナーが管理画面の「お知らせ」で内容を確認し、「公開する」に切り替えて保存すると公開される（数分でサイトに反映）。
5. history.csv の status を実際の状態に合わせて更新する（draft / needs_review / published / failed）。published_url は公開を確認してから入れる。

## 本文の書き方（お知らせの本文の記法）
- 段落は空行で区切る。行頭が「## 」の段落は見出しになる。
- リンクは `[文字](/system/)` の形だけ使える（HTMLは使わない）。
- 守ること：料金・割引・出勤・空き状況を推測で書かない／医療的な効果を断定しない／性的な連想をさせる表現を使わない／写真から性格や技術を推測しない／順位を約束しない。

## 毎日の手動実行用メッセージ
> この指示書と制作履歴に従い、日本時間の本日分の記事を1本作成してください。既存記事と最新の店舗情報を確認し、同じ疑問への回答が重複しないテーマを選んでください。記事本文、SEO項目、内部リンク、Googleビジネスプロフィール用の投稿案、制作履歴を出力してください。未確認の料金・出勤・空き状況は書かないでください。
