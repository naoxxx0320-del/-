# 予約管理システム（AROMA DAIAMOND）— Phase 1

WEB・LINE・電話の予約を **1つの台帳**に集約し、スタッフが登録・変更・確定・
キャンセルできる小規模予約管理システムです。チョイスリザーブのような運用を、
**Google Apps Script ＋ Google スプレッドシート ＋（LINE署名検証の）無料プロキシ**
という最小構成で実現します。会員・オンライン決済・売上分析は対象外です。

> **重要（現状）**：このPhase 1は**コード一式＋手順＋ロジックの自動テスト**までです。
> あなたのスプレッドシート／LINE／メールには当方から接続していません。
> デプロイ・シークレット設定・移行・本番切替は本READMEの手順で行ってください。
> 「実サービスで未確認の項目」は末尾に明記しています。**未接続の状態を『連携完了』
> とはしません。**

---

## 1. 採用した構成と理由

| 項目 | 採用 | 理由 |
|---|---|---|
| データ保存 | Google スプレッドシート「予約台帳」1枚 | 既存運用（出勤・WEB/LINE予約）と同じ基盤。追加コストなし。 |
| バックエンド | Google Apps Script（`Code.gs`＋`lib.gs`） | 既存のWEB/LINE予約がGAS。`LockService`で重複を安全に防げる。 |
| 認証 | **Google アカウント許可リスト** | パスワード管理不要・最も安全。管理画面はGoogleログインで保護。 |
| 管理画面 | Apps Script 配信（`Admin.html`） | URLを知るだけでは入れない（Googleログイン＋許可リスト＋サーバ側で権限確認）。 |
| LINE署名検証 | **Cloudflare Worker（無料）** | GASは受信ヘッダを取得できず厳密な署名検証が不可。Workerで検証して中継。 |
| 空き状況 | 公開API（個人情報なし） | 名前・電話・メール・メモを一切返さない。取得失敗は「空き」と誤表示しない。 |

GitHub Pages だけでは認証付きの安全な予約更新は実現できないため、更新系は
すべてGAS（認証・ロック・サーバ側検証）に置きます。フロントにパスワードは
置かず、管理画面を隠すだけの方式も使いません。

## 3. 台帳スキーマ（シート「予約台帳」）

| 列 | 内容 |
|---|---|
| 予約ID | 一意のID（例 `BK20261005...`） |
| 経路 | WEB / LINE / 電話 |
| 状態 / 状態ラベル | `tentative`(仮予約) / `confirmed`(確定) / `cancelled`(キャンセル) / `expired`(期限切れ) |
| 担当者ID / 担当者名 | 安定ID（既定は名前をキー）と表示名 |
| 開始(JST)/終了(JST) | 人が読む表示 |
| 開始epoch/終了epoch | 比較に使う正準値（TZ非依存。日またぎも正しく扱う） |
| 所要分 / コース / 料金 | 予約時点の料金を保存 |
| お客様名 / 電話 / メール / LINE_UID | 連絡先（メールは必須にしない＝電話予約に対応） |
| 仮予約期限epoch / 確認トークン | メール確認方式・TTL解放に使用 |
| 冪等キー | 再送・Webhook再送の二重作成を防ぐ |
| スタッフメモ | 自由メモ |
| 作成日時 / 更新日時 / 最終操作者 | 監査情報 |

別シート「**予約履歴**」に、作成・変更・確定・キャンセルの**変更前後と操作者**を
記録します（キャンセルは削除せず履歴として残ります）。

## 4. セットアップ手順

### 4-1. Apps Script プロジェクト
1. 予約台帳を置くスプレッドシート（**出勤情報と同じブック**推奨）を開く
2. **拡張機能 → Apps Script**
3. `lib.gs` / `Code.gs` / `Admin.html` の3ファイルを追加して内容を貼り付け
   （`Admin.html` は「ファイル → HTML」で `Admin` という名前で作成）
4. **プロジェクトの設定 → スクリプト プロパティ** に登録：

| プロパティ | 値 |
|---|---|
| `SHEET_ID` | スプレッドシートID（URLの `/d/ここ/edit`） |
| `STAFF_EMAILS` | 管理画面を使うスタッフのGoogleメール（カンマ区切り） |
| `TENTATIVE_TTL_MIN` | 仮予約の確認期限（分）。未設定なら30 |
| `PROXY_SHARED_SECRET` | 任意の長いランダム文字列（Workerと同じ値） |
| `OWNER_EMAIL` | 店舗通知メール（任意） |
| `TEST_MODE` | 検証中は `true`（メール送信せずログのみ） |

5. エディタで関数 **`setup`** を1回実行 → 権限承認 → 「予約台帳」「予約履歴」
   シート作成＋5分おきの期限切れ解放トリガーが登録されます。

### 4-2. デプロイ（**2つ**のウェブアプリ）
同じプロジェクトから、用途別に2つのデプロイを作ります。

- **公開API用**：デプロイ → 新しいデプロイ → ウェブアプリ
  - 実行：**自分** ／ アクセス：**全員**
  - → 発行URL（/exec）を控える（`GAS_EXEC_URL`・WEB予約/空き状況/ LINE中継先）
- **管理画面用**：もう1つデプロイ
  - 実行：**アクセスしているユーザー** ／ アクセス：**Googleアカウントを持つ全員**
  - → このURLがスタッフ用管理画面（Googleログインが要求される）
  - ※ スタッフの各Googleアカウントに、台帳スプレッドシートの**編集権限を共有**してください（管理操作はスタッフ権限で台帳に書き込むため）。

### 4-3. 管理画面の利用
- スタッフは「管理画面用URL」を開く → Googleログイン
- `STAFF_EMAILS` に登録され、かつ台帳に編集権限があるアカウントのみ操作可能
- URLを知っているだけ・ログインしていないだけでは一覧もAPIも使えません

## 5. データ移行とバックアップ

`Code.gs` の **`migrateFromLegacy`** を使います（要スタッフ権限）。

1. まず `migrateFromLegacy({dryRun:true})` を実行 → 取り込める件数/スキップ件数を確認
2. 問題なければ `migrateFromLegacy({})` を実行
   - **実行時にスプレッドシート全体のバックアップ（複製）を自動作成**します
   - 既存「予約」「LINE予約」タブは**消さず残します**（読み取りのみ）
   - 冪等キーで**重複取り込みを防止**。日付/時刻/担当者を解釈できない行はスキップしログ化
3. 旧「9/16(水)」形式など年が無い行は現在年で補完します。**年跨ぎは手動確認**してください

> まず**テスト用のコピーブック**で `migrateFromLegacy` を試すことを推奨します
> （`SHEET_ID` をコピーブックのIDにして検証 → 問題なければ本番IDへ）。

## 6. WEB・LINE との連携（本番切替の手順）

> ここは**本番切替**にあたるため、テスト検証後に実施してください。当方では
> 実環境に接続していないため、以下は手順として提供します。

### 6-1. WEB予約（サイト → 新バックエンド）
現在 `data/reserve-config.json` の `endpoint` は旧Apps Scriptを指しています。
新しい公開APIに切り替える際は：
- `app/reserve/page.jsx` の送信を `POST {action:"web_create", ...}` にし、
  **`mode:"no-cors"` をやめて JSON レスポンス（`{ok,id,status}`）を読み**、
  `ok:true` のときだけ完了画面を表示（＝通信失敗を成功表示しない）。
- 空き状況の取得は `?action=availability&date=YYYY/M/D&callback=...` を使い、
  **取得失敗（`ok:false`）時は「空き」と見なさない**。
- これらはテスト台帳・テストエンドポイントで確認後に切り替えます（Phase 2で実装予定）。

### 6-2. LINE予約（署名検証 → 同じ台帳）
1. `proxy/line-verify-worker.js` を Cloudflare Worker としてデプロイ
   - 環境変数：`LINE_CHANNEL_SECRET` / `GAS_EXEC_URL`(公開API) / `PROXY_SHARED_SECRET`
2. LINE Developers の **Webhook URL を Worker の URL** に変更（検証も通ります）
3. 既存 `line-booking.gs` を**同じGASプロジェクト**に置き、次の2点を変更：
   - `doPost` の先頭で、`JSON.parse(e.postData.contents).proxySecret` が
     `PROXY_SHARED_SECRET` と一致することを確認（不一致は拒否）。生のLINEイベントは
     `JSON.parse(body.lineBody).events` から取得。
   - 予約確定（`finalizeBooking`）で独自シート書き込みの代わりに
     **`createBooking({source:"LINE", ...})`** を呼び、**同じ台帳**へ記録。
   （この2点の具体パッチはPhase 2で提供します。Worker自体は今回同梱済み）

## 7. セキュリティ・個人情報

- 管理APIは毎回 `requireStaff_()` で Googleアカウント許可リストを検証
- 管理画面URLを知っているだけ・未ログインではアクセス不可（サーバ側で拒否）
- 公開の空き状況APIは**担当者ID・時間区間・状態のみ**（名前/電話/メール/メモを含めない）
- 認証情報・シークレットは**スクリプトプロパティ / Cloudflare Secret**にのみ保存。
  コード・公開JSON・`NEXT_PUBLIC_*` には入れません
- お客様情報は公開リポジトリやログに出しません（履歴はスプレッドシート内のみ）
- LINEは**Workerで署名検証**した正規Webhookのみ通します

## 8. 検証結果（この環境で実施できたもの）

純ロジックの自動テスト（`tests/logic.test.mjs`）が **全11件パス**：

- 日時のJST変換（TZ非依存）／**翌表記・日またぎ**の正しい扱い
- コース所要分の算出
- 区間重複判定（**一部重複を検出**・端の接触は非重複＝連続予約OK）
- 出勤内判定（コース終了が勤務終了を超えないか）
- 重複検出（**同一担当者のみ**・キャンセル/期限切れは枠を占有しない・自己除外）
- 冪等キー（**同一リクエスト/Webhook再送で二重作成しない**）
- 仮予約の期限切れ判定・状態遷移の妥当性（不正遷移を拒否）

実行：`node apps-script/booking/tests/logic.test.mjs`
