# URLを送って参加してもらう抽選

表示用のキャンペーン条件欄は削除し、「当選した結果はスクリーンショットを撮ってください。」という案内を大きく表示しています。1等の新しい確率は0.01％（10,000分の1）です。1等の上限3名、締切、保存済み結果の扱いは維持し、2〜4等は各33.33％としています。Google側に既にデプロイしたコピーは、更新済みコードへの差し替えと新しいバージョンのデプロイが必要です。


LINE Developers・LIFFの設定は不要です。参加者は共通のURLを開いて宝石を選び、その場で結果を確認します。LINEでURLを送ることもできますが、抽選時のLINEログインや友だち追加の確認はありません。

## サイトの本番移行

`/lottery/` は本番用の参加入口です。`data/lottery-public-config.json` の `participationUrl` が空、または `verified` がtrueでなければ「準備中」を表示し、抽選ボタンを出しません。体験版は `/lottery-demo/` に移しました。

`/lottery-setup/` は管理者向けの設定ページです。公開後はブラウザーでコードのコピー・表示・ファイルダウンロードができます。Google側の抽選アプリをデプロイし、実接続を確認した後、安定した `/exec` URLと `verified: true` を本番設定へ反映します。URLが未発行の状態を本番稼働済みと扱いません。

サイトのデプロイ前に、CIが抽選用ファイルを生成し直し、抽選・初期設定・公開リンクの検証を行います。生成した公開用コピーコードに秘密鍵や顧客情報は含みません。

本番移行用のローカル確認では34件のテストと35ページの静的ビルドが成功しています。Chromiumで準備中の受付停止、体験版の別ルート、管理者ページのコードコピー・正しいファイルのダウンロード、320px/390px/1440pxの表示を確認しました。サイト公開とGoogle側の抽選サーバー公開は別の作業です。

## 今回の参加制限

参加方法の質問への回答を待つ間、手軽な「共通URL＋同じブラウザーで1回」を用意しました。ブラウザーにランダムな参加識別子だけを保存し、抽選結果はサーバーの台帳に保存します。同じ識別子による再試行・再読込は既存結果を返します。保存できない場合は抽選を開始しません。

同じ人が別端末・別ブラウザー・プライベートモード・保存データ削除で再参加することは防げません。1人1回を厳密に確認する仕様ではありません。利用者自身が識別子を作り直せるため、意図的な複数参加にも弱い方式です。より強い制限を希望する場合は、個別参加URLやSMS認証への変更が必要です。

1等0.01％・全体で最大3名という上限は、サーバー側の台帳とロックで管理します。残りの賞は各33.33％・人数上限なし・ハズレなし。1等枠終了後は2〜4等を各3分の1で抽選します。開催期限は2026年11月30日23:59まで（日本時間）、特典の有効期限は無期限です。特典を1回だけ使う管理は未実装です。

## 管理者が公開する手順

1. [Googleスプレッドシート](https://sheets.google.com/)で新しい非公開シートを作り、「AROMA DIAMOND URL抽選台帳」と名付けます。
2. 「拡張機能 → Apps Script」を開き、初期コードを `apps-script/lottery-url-install.gs` の内容すべてに置き換えて保存します。既存の予約Webhook・旧LINE抽選用プロジェクトは使用しません。
3. 実行対象を `setupUrlLottery` にして実行し、自分で作成したスクリプトへのGoogleの権限許可を確認します。チャネルID等の入力は不要です。専用台帳とシート接続が作られます。
4. 「デプロイ → 新しいデプロイ → ウェブアプリ」を選びます。実行ユーザーは「自分」、アクセスできるユーザーは「全員」（匿名アクセスを含む設定）にします。この選択をGoogle側で許可できない場合、一般参加者はログインなしで参加できません。
5. 発行された末尾 `/exec` のURLが参加URLです。LINE・メールなどで送れます。開発用 `/dev` URLは配りません。

画面もApps Scriptが配信するため、サイト本体の公開や別オリジンへのブラウザーPOSTはこの方式では不要です。HTML Serviceの `google.script.run` で同じプロジェクトの抽選関数を呼びます。`public/lottery-url.html` 単体をサイトへ置いただけでは正式な抽選は動かず、「準備中」で停止します。

## 公開前の確認

本番とは別の新しいシートとテスト用キャンペーンで、スマホから表示・抽選・再読込・通信失敗からの結果取得を確認します。本番の3名枠をテストで消費しません。実Apps Scriptでの結合試験はまだ未実施です。発行されたURLで表示と接続を確認してから利用者へ送ってください。

更新は `node scripts/build-lottery-line.mjs`、続いて `node scripts/build-lottery-url.mjs` で生成し直します。旧LINE連携用ファイルは残っていますが、今回配るのはURL用のデプロイです。Google側の管理者ログイン・実際のデプロイは、このクラウド環境からは行えていません。
