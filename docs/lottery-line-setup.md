# LINEアカウントにつき1回の抽選

**旧方式の資料です。現在はURLを送って参加する方式へ変更しました。** 今回の設定は [URL抽選の公開手順](lottery-url-setup.md) を参照してください。LINE Developers・LIFFの設定は不要です。このLINE用プロジェクトへURL用コードを上書きしません。

管理画面での入力順序は [公式LINE設定手順](lottery-quick-start.md) を参照してください。`node scripts/build-lottery-line.mjs` が、新しいスプレッドシートから初期設定できる一式 `apps-script/lottery-install.gs` も生成します。

## 実装した範囲

- `public/lottery-line.html` と `lottery-line.js` が正式版への接続準備ページです。LIFFで取得するIDトークンとアクセストークンをPOSTし、サーバーが返した結果だけを表示します。設定が空、本人確認失敗、通信失敗の場合は抽選できません。
- `apps-script/lottery.gs` が別のGoogle Apps Scriptプロジェクトで動くサーバー処理です。LINE公式APIでトークン、チャネル、ユーザー一致、友だち状態を検証します。ブラウザーから送られたユーザーIDや友だちフラグは信用しません。
- キャンペーンIDとLINEユーザーIDから作るハッシュを台帳に保存します。同じアカウントへの再要求は、端末、宝石、時間を変えても以前の結果を返します。受付終了後も本人確認できれば既存結果を取得できます。
- 保存はScriptLock内で読み取り→判定→追加→flushします。同時リクエストを直列化し、重複抽選と各等の当選上限の超過を防ぎます。1等の上限は以前の3名枠を引き継ぎます。台帳への保存後に通信が途切れた場合は、「参加資格・結果を再確認」で保存済み結果を取得します。
- ダウンロード用 `lottery-mobile.html` は従来の体験版です。LINE本人確認・参加制限は含みません。体験版を正式な抽選として配布しないでください。

## 管理の単位

保証するのは「同じキャンペーンで1つのLINEアカウントにつき1回」です。複数のLINEアカウントを持つ同一人物の重複までは識別できません。ブラウザーの保存削除、別ブラウザー、別端末で制限を解除することはできませんが、管理者が台帳を削除したりキャンペーンIDを変更すると別参加になります。

## 必要なLINE設定

1. LINE DevelopersでLINEログインチャネルを確認または作成します。公式LINEと同じプロバイダーにまとめ、LINEログインチャネルへ対象の公式アカウントをリンクします。
2. LIFFアプリを作成し、スコープ `openid` と `profile` を有効にします。エンドポイントは正式に公開する `https://aroma-daiamond.com/lottery-line.html` とします。LIFF IDとLINEログインチャネルIDは公開識別子で、秘密鍵ではありません。
3. 開発状態のままの場合はテスト対象者の権限を確認します。第三者に公開する前にLINE側の公開状態も確認します。

## サーバー設定

既存のLINE予約Webhookには追加せず、専用のApps Scriptプロジェクトに `lottery.gs` を入れます。既存Webhookと同名の `doPost` を置き換えないためです。

専用の非公開スプレッドシートを作り、Apps Scriptのスクリプトプロパティに次を設定します。

| 名前 | 内容 |
| --- | --- |
| LINE_LOGIN_CHANNEL_ID | LINEログインチャネルID（Messaging APIのIDと取り違えない） |
| LOTTERY_SHEET_ID | 専用の非公開スプレッドシートID |
| LOTTERY_CAMPAIGN_ID | 開催中に変えない一意のキャンペーンID |
| LOTTERY_STARTS_AT | 開始日時。ISO形式で `+09:00` 等のタイムゾーンを付ける |
| LOTTERY_ENDS_AT | 終了日時。同じくタイムゾーン必須 |
| LOTTERY_PRIZE_RULES | 1〜4等すべての確率・当選枠を指定するJSON配列。設定例から転記 |
| LOTTERY_EXHAUSTED_PRIZE_POLICY | 今回は `equal_lower`。1等枠終了後は2〜4等を各3分の1で抽選 |

賞品は、1等「施術90分無料」、2等「衣装チェンジ無料」、3等「写真指名無料」、4等「パウダートリートメント無料」です。台帳のoutcomeには `prize_1`〜`prize_4`、または `lose` を保存します。以前の `win` の記録は削除・再抽選せず1等として読み取り、1等枠にも数えます。

`LOTTERY_PRIZE_RULES` は4つのオブジェクトを含むJSON配列です。各項目に `id`（1〜4）、`probability`（0〜1の数値）、`maxWinners`（0以上の整数、または主催者が上限なしを選んだ場合のnull）を必ず指定します。1等の `maxWinners` は3です。確率の合計は0より大きく1以下にし、1との差がはずれの確率になります。設定が不完全な場合は抽選を開始しません。以前の `LOTTERY_WIN_PROBABILITY` だけでは開始できません。

今回の設定は `data/lottery-campaign.json` を正本として、`node scripts/build-lottery-line.mjs` で `apps-script/lottery-properties.example.json` に出力します。設定例の空欄（LINEログインチャネルIDとスプレッドシートID）を実際の値で埋め、専用Apps Scriptのプロパティへ転記します。JSON配列は文字列の値を転記します。秘密鍵は不要で、トークンをこのファイルに入れません。

1等は0.1％（1,000分の1）、最大3名。2〜4等は各33.3％、人数上限なし。`equal_lower` は2〜4等の上限なし・均等確率を必須とし、設定が違えば停止します。1等枠が埋まった後は、残り3等級を各3分の1としてハズレを出しません。旧設定用の `lose` ポリシー（未指定時も同じ）は、枠終了分をハズレへ回す従来動作を維持します。上限3名は必ず3名が当選する保証ではありません。

開催期限は2026年11月30日23:59まで（日本時間）です。`LOTTERY_ENDS_AT` は排他的な `2026-12-01T00:00:00+09:00` としました。開始日は10月6日00:00の仮置きで、実際の受付は公開後です。期限を延長してもキャンペーンIDは変更せず、既存の参加制限・抽選結果を維持します。特典有効期限は無期限です。抽選の締切と特典の使用期限を分け、締切後も保存済み結果を返します。ただし特典の使用記録・1回使用管理は未実装です。

ウェブアプリとして「実行ユーザー＝所有者」でデプロイし、LIFF利用者がPOSTできるアクセス設定を選びます。エンドポイント自体を公開しても、抽選・結果取得にはサーバー側のLINE本人確認が必須です。スプレッドシートは公開・共有リンクを有効にしません。

`public/lottery-line-config.json` にLIFF ID、ウェブアプリのHTTPS `/exec` URL、同じキャンペーンIDを設定します。このJSONにトークン、チャネルシークレット、個人情報を入れません。利用者のトークンはLIFFから一時取得し、HTMLやlocalStorage、ログに保存しません。

## 接続確認と公開前の条件

- 本番のLIFF、公開オリジン、Apps Scriptの組み合わせで、URLSearchParamsによるPOSTとJSON結果の読み取りを確認します。CORS等で読めない場合は参加を停止する設計です。`no-cors`、JSONPのURLへのトークン付与、ローカル乱数への置き換えで回避しません。必要ならCORSを正しく扱える認証APIホストへ移します。
- 実際のLINE認証、友だち未追加、別端末、同時リクエスト、期限前後、各等の当選枠、保存後の通信失敗をテスト用台帳・テスト用キャンペーンで確認します。
- 未設定状態では「準備中」で停止します。接続試験未完了の状態を利用者向けに公開しません。
- 期間、確率、枠終了後の扱い、有効期限は画面へ反映済みです。正式公開時には対象コース、予約時の利用条件を決めて表示し、「準備ページ」の表示を開催用に調整します。当選受付番号は抽選記録の識別子です。クーポンの1回使用管理は別機能で、まだありません。
- ここからの実際のWeb公開、LINE設定、Apps Scriptデプロイは未実施です。

## 再生成とローカル検証

モバイル体験版のデザイン更新後は `node scripts/build-lottery-line.mjs` で接続準備HTMLを再生成できます。抽選サーバーの検証は `node --test scripts/lottery-server.test.cjs` で実行します。これは公式LINE・Googleの実サービスとの結合試験ではありません。

初期設定一式の検証は `node --test scripts/lottery-setup.test.cjs` で行います。3件のローカルテストで、設定保存・再実行時の台帳保持、別キャンペーン等への上書き拒否、キャンセル・入力誤り・ロック失敗・台帳の形式不一致・保存失敗時に設定を書き換えないことを確認しています。Apps Scriptの実管理画面での操作はまだ確認できていません。

今回、サーバー処理の22件のテストが成功しました。各等の正しい保存と再表示、当選枠の維持、設定不足時の停止に加え、1等0.1％・下位各33.3％の区間分配、1等枠終了後の下位均等当選、日本時間の締切境界、締切後の既存結果保持を確認しています。LINE SDKとAPIを模したブラウザー試験では、未設定時の抽選停止、認証後の抽選、連打防止、新しいブラウザー環境からの保存済み結果の表示、保存後の通信失敗からの復帰を確認しています。データ検証と33ページの静的ビルドも成功しました。既存の写真未設定・案内データの古さ・Google Fonts最適化のスキップは残っています。実LINE・Apps Scriptとの結合試験は未実施です。
