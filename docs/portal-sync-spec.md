旧版（v1.0）からの主な変更：確認済みの事項を「決定事項」に移し、入力元を今の仕組みに一本化し、作業の順番・完成の基準・止まる条件を具体的にした。

## 0. この指示書の読み方
- 「決定事項」はオーナーが決めたことで、変えない。変えたほうがよい理由があれば、変える前にオーナーに提案する。
- 「着手前の確認」が全部そろうまで、ポータルに書き込むコードは作らない（読み込み・画面の調査・雛形づくりまでは進めてよい）。
- 各段階（フェーズ）の終わりに、実際に動かした結果をオーナーに見せ、承認を得てから次へ進む。
- 説明はオーナー（開発の専門家ではない）に向けて平易な日本語で書き、専門用語には一言説明を添える。

## 1. 目的
お店の情報を**今の仕組み（管理画面・出勤のスプレッドシート・サイトのデータ）に入力するだけで**、掲載中のポータルサイト5つの店舗管理画面へ、同じ内容を確認つきで反映できるようにする。
ねらいは次の3つ。
1. 二重・四重の入力の手間をなくす
2. サイトと各ポータルで、料金・出勤・割引などの内容がずれないようにする
3. 反映した内容と結果を記録に残す

## 3. 入力元と反映先の対応表
入力はすべて今の仕組みで行う。今の仕組みに入れる場所がない項目（求人・ポータル用の紹介文・口コミ返信の文面）だけ、**今の出勤スプレッドシートに新しいタブを足す**。

| 反映する内容 | 入力する場所（正の情報源） | ツールの読み方 |
|---|---|---|
| 出勤情報（日付・時間・セラピスト） | 出勤スプレッドシート「出勤情報」（管理画面のシフト表から入力） | シートの公開CSV（サイトと同じURL。もともと公開している情報） |
| セラピスト情報（名前・年齢・紹介文・タグなど） | 出勤スプレッドシート「本日の出勤」（管理画面のプロフィール編集） | 同上 |
| 写真（セラピスト・店舗・ルーム） | サイトの写真（リポジトリの public/。管理画面から登録） | リポジトリの最新版を取得 |
| 料金・コース・指名料・オプション | data/price.json | 同上 |
| 割引・クーポン・イベント | data/offers.json（終了日のある割引は自動で外す） | 同上 |
| 店舗情報（営業時間・受付時間・アクセス・支払い方法） | app/_lib/site.js・data/price.json など、サイトの表示と同じデータ | 同上 |
| お知らせ・ブログ | data/news.json（公開中の記事だけ） | 同上 |
| 求人情報 | **新タブ「求人」**（募集内容・待遇・応募方法）。サイトの求人ページと内容をそろえる | Google Sheets API（読み取り専用の権限） |
| ポータル別の上書き（文字数が足りない・選択肢が違う項目） | **新タブ「ポータル別設定」**（サイト名・項目・上書きする値） | 同上 |
| 口コミへの返信 | ツールが各ポータルの新しい口コミを一覧にする → 返信文はオーナーが書く（Claude に下書きを頼んでもよい）→ **新タブ「口コミ返信」** で承認 | 同上 |

守ること：
- **予約台帳・お客様の情報（名前・電話・メール・メモ）は読まない。** ツールが読むのは、サイトに公開しているのと同じ情報と、上の新しいタブだけ。
- 新しいタブを読むための権限は「読み取り専用」にする。シートを新たに「ウェブに公開」することはしない。
- 口コミの本文やニックネームはポータル上の情報だが、ツールの記録（ログ）には必要最小限だけ残し、リポジトリには入れない。

**公開されている利用規約の確認結果（2026-11-25、Claude が本文を確認）**
- エステ魂・エステ番長：掲載店向けの規約に「提供サービスの利便性…を著しく妨害する行為」の禁止などがある。自動ツールについての明記はない。→ 6章のとおり、アクセスの間隔をあけ、短時間に大量のアクセスをしない。
- エステラブ・全国メンズエステランキング：公開の利用規約は主に閲覧者向けで、「不正アクセス」「有害なプログラム」の禁止はあるが、店舗管理画面の自動操作についての明記はない。
- 駅ちか：トップページから規約のページを確認できなかった（掲載店向けの案内ページはある）。
- 運営会社からは、オーナーの電話の問い合わせで「問題ない」との回答を得ている（上の表の1）。今後、規約の変更や運営会社からの連絡があった場合は、そのサイトの反映を止めてオーナーに確認する。

## 5. 作り方の方針
- 置き場所：このリポジトリの `tools/portal-sync/`（サイトの公開ファイルには含めない）
- 言語・道具：Node.js（20 LTS）＋ TypeScript、ブラウザ操作は Playwright（画面が見えるブラウザで動かす）
- **サイトごとに独立した部品（コネクタ）**にする。1つのサイトの画面が変わっても、他のサイトの反映は止まらない
- 各コネクタは次の4つの働きを持つ：①ログイン ②今の登録内容を読む ③書き込む ④書いた結果を読み直して確かめる
- **練習モード（何も書き込まない）を標準**にし、書き込みはオーナーの承認後だけ行う
- 起動：Mac のデスクトップに置いた「ポータル更新.command」をダブルクリック、またはターミナルでコマンド1つ

### 動作の流れ（1回の実行）
1. 入力元を読み込み、入力内容を点検する（日付・時間の形、必須項目、文字数）。誤りがあれば一覧で表示し、そこで止める
2. 各サイトにログインし、今の登録内容を読む（ログインはオーナーのキーチェーンの情報で自動。画像認証・2段階認証が出たら、ブラウザ上でオーナーが入力するのを待つ）
3. 「どのサイトの・何を・どう変えるか」の一覧（変更点の一覧）を表示する。変更前と変更後を並べて見せる
4. オーナーが確認し、サイトごと・項目ごとに「反映する／しない」を選んで承認する
5. 承認された項目だけ、人の操作に近い間隔（1操作ごとに数秒）で、1サイトずつ書き込む
6. 書き込んだ後に登録内容を読み直し、入力どおりになっているか確かめる
7. サイトごと・項目ごとに「成功／失敗／見送り」を表示し、記録（ログ）とスクリーンショットを Mac に保存する
8. 失敗した項目だけを、次の実行で選んでやり直せる

### 変更点の決め方
- 正しい比べ方は「ポータルに今登録されている内容」と「入力元」の比較。読み取れない項目だけ、前回反映した内容の控え（Mac に保存）と比べ、その旨を一覧に表示する
- ポータル側でだけ変わっていた項目（誰かが管理画面で直接直した等）は、上書きする前に一覧で知らせる

## 6. 守ること（安全と品質）
0. **反映するのは実際の情報だけ**：出勤は、出勤スプレッドシートに入っている実際の出勤だけを反映する。実在しない出勤（ダミー）・在籍していないセラピスト・実際と違う料金や割引を、ツールで登録しない。ポータルにダミーの出勤が残っている場合は、差分として一覧に出し、オーナーの確認を得て取り消す
1. **ログイン情報**は Mac のキーチェーンに保存する。コード・スプレッドシート・設定ファイル・Git には書かない。ログイン状態の保存ファイル（Cookie など）は Mac の利用者フォルダに置き、他人が読めない権限にし、Git に入れない
2. **画像認証・2段階認証の自動突破・回避はしない**。出たら止まってオーナーの入力を待つ
3. 規約で禁止された操作、アクセス制限の回避、1サイトへの短時間の大量アクセスをしない（同時に複数の画面を動かさない）
4. **削除・非表示の操作**（セラピストの退店、投稿の削除、割引の終了など）は、通常の承認とは別に1件ずつ確認してから行う
5. **口コミへの返信**は、オーナーが承認した文面だけを、1件ずつ投稿する。返信文を自動で作って投稿することはしない
6. 画面の作りが変わって入力欄やボタンが見つからないときは、**推測で書き込まず、そのサイトを止めて報告**する（他のサイトは続ける）
7. 記録（ログ）には、パスワード・お客様の個人情報を残さない。スクリーンショットとログは Mac にだけ保存し、30日たったら消す
8. 実際に動かして確かめていないものを「完成」「テスト済み」と報告しない
9. 今のサイト・予約・LINE・管理画面の動きを変えない。今の仕組みに手を入れる必要があるときは、先にオーナーに説明して承認を得る

## 7. 進め方（フェーズ）と完成の基準
| フェーズ | やること | 完成の基準（オーナーに見せるもの） |
|---|---|---|
| 0 準備 | 着手前の確認（4章）の残りを進める。Remote Control で5サイトの管理画面を調べ、入力欄・文字数・写真の決まり・公式の一括更新の機能の有無を表にまとめる。新しいタブ（求人・ポータル別設定・口コミ返信）の雛形を作る | 5サイトの「項目の対応表」、雛形のタブ |
| 1 読み込み | 入力元の読み込みと点検、Mac への導入手順、練習モードの変更点一覧（ポータルにはまだ接続しない） | 実データで点検と一覧が出ている画面。導入手順どおりにオーナーの Mac で動いたこと |
| 2 最初の1組 | **エステ魂 × 出勤情報** だけを完成させる（読み取り → 変更点 → 承認 → 書き込み → 読み直し → 結果） | 実際に1回反映し、ポータル上の表示がスプレッドシートと一致したスクリーンショット |
| 3 項目を増やす | エステ魂で、セラピスト → 写真 → 料金・店舗 → 割引 → お知らせ → 求人 → 口コミ返信 の順に1つずつ | 項目ごとに、実際の反映結果と一致の確認 |
| 4 サイトを増やす | 残りの4サイトを1つずつ（出勤から順に）。順番はフェーズ0の調査結果を見てオーナーと決める | サイトごとに、フェーズ2・3と同じ確認 |
| 5 仕上げ | 失敗時のやり直し、記録の整理、使い方の説明書 | オーナーが説明書だけで1回最後まで操作できたこと |

- 1回の作業で扱うのは「1サイト × 1項目」まで。次へ進むのはオーナーの承認後。
- 本番のポータルで試すときは、影響の小さい項目（例：翌日以降の出勤1件）から始め、試した内容と元に戻す方法を先にオーナーに伝える。

## 8. 毎回の報告に含めること
1. できたこと／できていないこと／オーナーに確認したいこと
2. 変更したファイルと理由
3. 実際に動かした結果（スクリーンショット、成功・失敗・見送りの一覧）
4. オーナーが Mac で行う操作（番号付きの手順、専門用語なし）
5. 弱点（ポータルの画面変更で壊れやすい所）と、壊れたときの直し方

## 9. 対象外（作らないもの）
- 画像認証・2段階認証の自動突破、アクセス制限の回避
- 他店のアカウント・情報の操作や収集
- 決まった時刻に無人で反映する仕組み（毎回承認するため）。必要になったら別途相談
- 口コミの返信文を自動で作って投稿すること
- 予約台帳・お客様情報の読み取り
